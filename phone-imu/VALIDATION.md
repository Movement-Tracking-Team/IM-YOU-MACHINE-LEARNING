## Practical acceptance test

1. **Connect:** Use a network that permits local connections. Open the setup page on all three iPhones, install/trust the CA, open the HTTPS phone link, select distinct phone numbers, and allow motion access. Confirm three Ready cards and fresh acceleration/gyro signals. Confirm the setup and recorder links use the computer's current address.
2. **Stationary check:** Place the phones flat for ten seconds. Each phone should report a nonzero actual rate; acceleration magnitude should be near gravitational acceleration and gyro values near zero, within each device's uncalibrated bias. A missing or null gyro is a failure, not zero-filled data.
3. **Shared start:** Press START. Observe the three-second countdown. Confirm all three acquire data before the boundary, and exported rows begin on or after the exact shared `start` timestamp. Sensor sampling phases need not coincide exactly.
4. **Rate and jitter:** Record at least 60 seconds. Calculate each phone's mean/median rate, interval SD, max interval and dropped/long event intervals from `phone_timestamp.diff()`. Note iPhone model, iOS version, Safari rate, temperature and mount. Report the actual rate, even if it is 60 Hz or lower. Do not require a browser to achieve a 100 Hz setting it cannot control.
5. **Physical alignment:** Secure all three phones to the same rigid support for this test. Apply five gentle, distinct taps or short rotations 5–10 seconds apart at the beginning and end of the recording. Use the converted common timestamps to compare corresponding acceleration/gyro features across phones. Report pairwise peak-time differences or cross-correlation lags, their spread, sample-period resolution, and whether the lag changes over time. Browser delivery/filtering can add delay beyond the clock estimate; do not label RTT/2 as measured sensor alignment.
6. **Disconnect recovery:** Keep the recorder page visible. Interrupt only one phone's network for about two seconds, then restore it. Check that its unacknowledged count grows and drains, other phones keep streaming, and sequence gaps return to zero. Switching to Settings can itself pause Safari; annotate any such acquisition gap separately from packet loss. Prefer router-side or controlled network interruption when measuring pure transport recovery.
7. **Shared stop/export:** Press STOP on the computer, wait for delivery complete, and download all four CSVs plus metadata. Confirm each device appears, no repeated `(device_id, packet_sequence_number, phone_timestamp)` rows exist, and all exported common timestamps lie in `[start, stop)`. Confirm `phone_timestamp - offset_s == common_timestamp` within floating-point tolerance.
8. **Failures:** Try duplicate phone numbers and denied sensor permission before a session. START must remain unavailable. Hide one page during a test and confirm a visible warning/Not Ready state; discard that acquisition as incomplete. Disconnect a phone during the start countdown and confirm the session cancels instead of claiming a coordinated recording.
9. **Longer session:** Repeat for ten minutes while phones remain foregrounded. Inspect `sync.jsonl` for periodic clock updates, estimate changes and RTT/uncertainty. Record backlog growth, sample jitter and any discontinuities before accepting longer sessions.

Retain a session note alongside the exported files with placement, movement labels, iOS/device versions, measured rates, clock estimates, observed physical alignment and any interruptions. The parent ML classifier's calibration and minimum sampling-rate requirements still apply.
